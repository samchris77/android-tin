# Tinnitus Tracker: Records Page & Tracking Architecture

## 1. App Layout & Navigation Flow (앱 레이아웃 및 탐색 흐름)

The Records section is designed to minimize user friction while maximizing data accuracy. It relies on a **Tabbed Interface** for data viewing and a **Passive Tracking System** coupled with a **Quick-Log Bottom Sheet** for data entry.

### Main Records Screen (기록 메인 화면)
* **Global Element:** A Floating Action Button (FAB) fixed at the bottom right (`+`) to trigger the Quick-Log Bottom Sheet.
* **Global Element (Conditional):** The `LiveSessionPill` floats at the top/bottom of the screen *only* when a therapy session is actively playing or in the 60-second pause debounce state.
* **Tab 1: Overview & History (요약 및 내역)**
    * **Top:** Weekly Summary Dashboard (Average Tinnitus Volume, Total Listening Time).
    * **Middle:** Month Tracker (Calendar with color-coded severity dots).
    * **Bottom:** Recent Entries List (Chronological list of auto-captured sessions and manual diary logs).
* **Tab 2: TFI Scores (TFI 검사 탭)**
    * **Top:** TFI Progress Line Chart.
    * **Middle:** Historical list of TFI assessments.
    * **Bottom Action:** Button to take a new TFI assessment.

### The Quick-Log Bottom Sheet (빠른 기록 바텀 시트)
Triggered by the FAB or by tapping an auto-captured session in the history list.
* **No Typing Required:** Uses Compose `FilterChip` or toggle buttons.
* **State:** If opened via a specific history item, it pre-fills the `duration` and `soundId`.
* **Inputs:**
    * **Volume/Distress:** 1-10 Sliders.
    * **Tags:** `[Relieved]`, `[Worse]`, `[Sleep]`, `[Stress]`, etc.
* **Action:** Large `[ Save / Update ]` button.

## 2. Core Logic: Passive Session Tracking (백그라운드 자동 기록)

The app tracks listening sessions automatically to guarantee compliance data.

1.  **Dominant Sound:** If a user switches sounds during a session, the app tallies the time for each and saves the session under the sound that was played the longest.
2.  **The 60-Second Debounce:** When paused, tracking doesn't end immediately. A 60-second countdown begins. If the user resumes play, the session continues seamlessly. If 60 seconds pass, the session is finalized.
3.  **Minimum Threshold:** Sessions under 5 minutes (300,000 ms) are discarded to prevent database clutter from accidental plays.
